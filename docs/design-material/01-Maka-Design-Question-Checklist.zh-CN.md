# Maka 设计问题清单（精华版）

> 只保留与 **Agent Harness 本身**相关的核心设计问题：日志与运行时、上下文投影与压缩、持久任务与恢复、验证与事实权威、工具系统与安全、评估、持续进化、多 Agent 协作。按 Maka 四条信条组织。每题标注对应知识点（KP-xx-xx），论据在 `agent-book-knowledge/` 可查。
>
> 用法：设计评审 checklist、设计文档的"开放问题"章节、需求澄清访谈。

---

## 一、Log is the Runtime（日志即运行时）

1. **Q-L1** Event Log 要覆盖哪些事件才算"日志即运行时"——模型决策、上下文输入、工具调用与结果、终止事实，缺哪一块，恢复就缺哪块证据？（KP-00-01）
2. **Q-L2** 工具结果存原始 payload 还是投影后内容？日志只增不改、投影可变，两者如何分储？（KP-02-02）
3. **Q-L3** 哪些事件必须入日志：状态栏注入、工具 schema 加载、护栏判定、权限检查、自检证据、恢复动作？没有日志的约束无法审计。（KP-01-09）
4. **Q-L4** 如何从 schema 层强制区分"证据（不可变）"与"结论（可变投影）"？（KP-08-01）
5. **Q-L5** TaskRun 的终止事实应否作为独立事件类型？恢复时如何识别"任务已终止"？（KP-02-03）
6. **Q-L6** 并行工具调用在日志里如何建模（一个 assistant 事件挂多个 tool_call + 多个 tool 结果）？（KP-02-03）
7. **Q-L7** 每个事件是否自带幂等键/操作 ID，支撑多 Agent 恢复与"仅结算一次"？（KP-10-10/10-11）
8. **Q-L8** 日志如何对齐 OpenTelemetry/OpenInference 的 span 树，避免被分析平台锁定？（KP-06-18）
9. **Q-L9** 临时结果（provisional）与确认事实（confirmed）如何在日志里区分，避免下游把临时态当最终事实？（KP-09-02）

## 二、Context is not history（上下文投影与压缩）

1. **Q-C1** "不能悄悄丢掉决定下一步行动所需的信息"——谁来判定哪些信息必需？需要显式"可丢弃声明"协议吗？（KP-02-01）
2. **Q-C2** 静态前缀（system+tools）与动态轨迹在投影里如何区分？日志里如何标记？（KP-02-05）
3. **Q-C3** Tool Result 剪枝会不会重演"缺工具结果→无限循环"？检测/终止机制如何兜底？（KP-02-05/02-09）
4. **Q-C4** 剪枝替换轨迹中部 tool result 时，如何量化"缓存重建代价 vs token 节省"？（KP-02-06）
5. **Q-C5** 压缩保留优先级怎么定？架构决策/验证状态/未解决 TODO 是否不得摘要？（KP-02-26）
6. **Q-C6** 上下文腐化（装得下但找不到）如何检测？能否用日志指标（重复调用、来回纠结）作信号？（KP-02-23）
7. **Q-C7** 状态栏是日志的确定性投影还是独立状态？模型无条件信任状态栏，准确率如何当一线指标盯？（KP-02-20/21）
8. **Q-C8** 状态栏更新用"每轮替换"还是"持久追加"？按轨迹长度/更新频率如何自动选择？（KP-02-22）
9. **Q-C9** 子 Agent 委派时任务描述必须自包含——主日志只记"派发+结论"，如何保证可审计？（KP-02-27）
10. **Q-C10** Skill 目录作为稳定前缀、正文追加进轨迹，如何与 KV Cache 字节级稳定配合？（KP-02-18/19）

## 三、A task may outlive a Turn（持久任务与恢复）

1. **Q-T1** TaskRun 的恢复点如何与"安全点"对齐——哪些日志事件构成可恢复检查点？（KP-04-17）
2. **Q-T2** 预算（budget）耗尽算"终止事实"还是"挂起事实"？续跑从哪个日志偏移恢复？（KP-02-04）
3. **Q-T3** 事件只在安全点被消费——取消式/队列式/并行式三策略如何落到调度语义？（KP-04-17）
4. **Q-T4** 同步 LLM 如何容忍异步打断？占位符五规则是否保留"常态完美同步轨迹"？（KP-04-17）
5. **Q-T5** 带外部副作用的工具（支付/发消息），恢复契约（幂等键/对账）如何做成平台约定？（KP-10-10）
6. **Q-T6** 熔断阈值从哪来？是产线数据统计（如"连续 3 次"）还是拍脑袋？（KP-05-05）
7. **Q-T7** 重复调用指纹、死亡螺旋如何用日志检测并终止？（KP-05-05）
8. **Q-T8** 失败时"重试当前子任务"还是"全局重规划"？判定依据是什么？（KP-09-15）

## 四、Feedback is not fact authority（验证、自检与事实权威）

1. **Q-F1** Self-check 是"有界修复"而非"无限重试"？连续失败后是否熔断并交还人工？（KP-01-15）
2. **Q-F2** Self-check 的"证据"限定为结构化字段吗？如何防提示注入借自检"洗白"？（KP-01-11）
3. **Q-F3** "承诺—行动一致性"检查如何在 TaskRun 日志上低成本实现？（声称已完成 vs 日志真实工具调用）（KP-08-04）
4. **Q-F4** 自检拒绝作为一条工具调用级事件进日志，让 Agent 用既有失败处理路径消化——如何落地？（KP-04-11）
5. **Q-F5** 验证器与"生成修改"的模块分离（裁判与进化解耦）——如何保证？（KP-08-03）
6. **Q-F6** 学习信号三类来源（环境结果/过程规则/LLM Rubric），确定性部分是否绝不交给模型？（KP-08-02）
7. **Q-F7** 一票否决维度（幻觉/安全）如何做校准/复核，避免误报压低整体评分？（KP-06-02）
8. **Q-F8** 任务完成事实由终态事件定义而非前台宣称——"办好了"如何固化进日志？（KP-09-14）

## 五、工具系统与安全（Harness 的"手脚"）

1. **Q-U1** 五类工具（感知/执行/协作/用户沟通/事件触发）如何进入 Event Log 成为一等事件？（KP-04-01）
2. **Q-U2** 能力表达：专用工具 vs Skill+通用执行器，三维决策（参数复杂度/变更频率/模型能力）如何落地？（KP-04-02）
3. **Q-U3** 工具描述"何时用/边界/反例/示例/代价"五字段是否强制？能否从失败日志反推描述缺陷？（KP-04-04）
4. **Q-U4** 执行工具安全层次（输入验证快速失败/权限/沙盒隔离）——进程级/容器/microVM 如何按部署选？（KP-04-10）
5. **Q-U5** Sidecar 安全校验只读结构化字段、不读模型自由文本——watchdog 是否照此设计？（KP-04-12）
6. **Q-U6** 参数传递保真性：工具不得静默改参数，任何改写作为显式事件记录——如何保证？（KP-04-05）
7. **Q-U7** 沙盒是否满足"默认无网络、限时/限 CPU/限内存/限输出"四条底线？（KP-01-03）
8. **Q-U8** 命令走语义解析而非黑名单——Maka 的 Bash 如何识别参数消费规则？（KP-05-09）
9. **Q-U9** 幂等与取消："副作用到底发生没有"如何回答？哪些操作需要"预检-确认"两段式？（KP-04-13）

## 六、评估（评估是地基）

1. **Q-E1** 评估单元=模型×Harness——Tool Result 剪枝、Compaction、Self-check 各属"模型能力"还是"Harness 设计"？model swap 如何判定？（KP-06-01）
2. **Q-E2** Pass@k（能力上限）与 Pass^k（业务可靠性）如何同时报告并写明口径？（KP-06-03）
3. **Q-E3** 每个 harness 特性是否可独立关闭做消融（裸模型基线）？开关是否在启动路径极早期注入？（KP-06-19）
4. **Q-E4** LLM-as-a-Judge 用前是否先做评判者校准（金标集+kappa）？同源模型问题如何强制引入异构 judge？（KP-06-06/06-13）
5. **Q-E5** 失败归因如何定位"首个错误"？结构化归因记录（步骤/工具/证据/置信度/主因次因）如何基于 Event Log 产出？（KP-06-14）
6. **Q-E6** 端到端回归 vs 轨迹前缀回归（冻结前缀只测下一步决策边界）——两类集如何维护？（KP-06-15）
7. **Q-E7** 统计显著性（置信区间/配对检验/多随机种子）是否内置到 comparison 输出？（KP-06-17）
8. **Q-E8** 生产 bad case→脱敏→回归集的回流闭环如何建？（KP-06-18）
9. **Q-E9** 分数下降时如何区分"评测系统问题"与"真实退化"，先查评测再动 Agent？（KP-06-19）

## 七、持续进化（headless / 自进化）

1. **Q-V1** "日志=运行时"不等于"日志=学习"——评价/归纳/验证层如何叠加在 Task Event Log 之上？（KP-08-01）
2. **Q-V2** 在线执行循环不直接改写正式 Agent，经验沉淀放离线循环——物理边界放哪？（KP-08-11）
3. **Q-V3** 四种更新载体（知识/指令/程序/参数）如何分流？按"载体能否自然表达"选择？（KP-08-05）
4. **Q-V4** 修改先成候选、灰度发布、指标恶化自动回滚——候选区→canary→正式状态机如何做？（KP-08-12）
5. **Q-V5** 安全边界三道隔离（证据与指令/候选与正式/安全机制不可自我修改）如何映射进文件权限？（KP-08-14）
6. **Q-V6** "完成"≠"进步"——代理指标改善但真实目标未动如何标记？（KP-08-13）
7. **Q-V7** 睡眠学习五步周期（触发—定向—整合—验证—修剪）如何与预算耦合？（KP-08-15）
8. **Q-V8** 可信根（评价器/权限边界/留出测试）如何保证在可修改范围之外？（KP-08-10）

## 八、多 Agent 协作（swarm）

1. **Q-M1** 2×3 矩阵（上下文共享×协作拓扑）——swarm 首期支持哪几格？（KP-10-01）
2. **Q-M2** 多 Agent 价值判据=是否引入"生成时不可得的新信息"——swarm 决策门如何做？（KP-10-05）
3. **Q-M3** 不共享上下文时移交包三部分（任务描述/已确认事实与约束/产物引用）——"已确认事实"与信条 4 如何衔接？（KP-10-15）
4. **Q-M4** Agent 互为工具（Manager 模式）+ 子 Agent 返回结构化摘要而非全量轨迹——如何落地？（KP-10-14）
5. **Q-M5** 共享工作区并发（乐观锁/worktree 隔离）——文件级与语义级冲突如何处理？（KP-10-18）
6. **Q-M6** 级联终止"一个成功、全员停止"——竞态（仅结算一次）如何用日志去重？（KP-10-11）
7. **Q-M7** 错误级联放大——移交/调度引用原始证据而非转述，交叉验证如何打断放大链？（KP-10-19）
